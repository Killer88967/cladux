## November 2026

### Accessibility

- Every docs page and block is now checked with [axe](https://github.com/dequelabs/axe-core) in light and dark mode on each change, and the problems it found are fixed:
  - Code is highlighted with GitHub's high-contrast light theme, so every color reads at 4.5:1 or better.
  - [Slider](/docs/components/slider) puts its `aria-label` on the thumbs, where screen readers look for it, so labelled sliders are announced by name.
  - [Calendar](/docs/components/calendar) day buttons are labelled with the number they show ("Sunday, March 1, 2026"), which voice control needs.
  - [Scroll Area](/docs/components/scroll-area) and [Virtual List](/docs/components/virtual-list) can be scrolled with the keyboard.
  - [Item](/docs/components/item)s inside an `ItemGroup` are list items, [Combobox](/docs/components/combobox)'s icon buttons have names, and [Rich Text Editor](/docs/components/rich-text-editor) takes a `label`.
  - The avatar fallback and trace details have enough contrast, and every demo's buttons, inputs and progress bars have names.
- In light mode, muted text and red (destructive) text are a little darker than shadcn's in every base color, so they read at 4.5:1 on the muted gray and on the pale red of destructive buttons, badges and alerts. Dark mode keeps shadcn's colors. For shadcn's exact light values, set `--muted-foreground: oklch(0.556 0 0)` and `--destructive: oklch(0.577 0.245 27.325)`.
- The plain HTML runtime, the site's search, theme customizer and copy buttons, and the CLI in fresh Next.js and Vite apps all have browser tests.

### Plain HTML

- [Plain HTML](/docs/html) has its own page: setup, the components that work without React, every attribute the script reads, `cl.toast()` and `cl.openDialog()`, and the layout helpers (`cl-stack`, `cl-cluster`, `cl-grid-auto`, `cl-container`).
- The stylesheet and the script are online, at `/cl/cl.css` and `/cl/cl.js`, so a page can link to them directly.
- They're on npm as [`cladux-html`](https://www.npmjs.com/package/cladux-html), so jsDelivr and unpkg serve each version at a link that never changes. Version 0.2.0 adds minified files, `cl.min.css` and `cl.min.js`.
- Five more components work without React: [Accordion](/docs/components/accordion#css-only) (no script needed), [Sheet](/docs/components/sheet#css-only), [Slider](/docs/components/slider#css-only), [Combobox](/docs/components/combobox#css-only) and [Carousel](/docs/components/carousel#css-only).
- The plain HTML [Dialog](/docs/components/dialog#css-only) no longer fills the whole height of the screen in Safari.
- The script sets up markup added to the page later, such as by htmx or a framework.
- Version 0.3.0 can [load only the components a page uses](/docs/html#only-the-components-you-use): `core.css` plus a file per component, such as `components/dialog.css`.
- The script is also an [ES module](/docs/html#as-an-es-module), `cl.mjs`, with TypeScript types, for bundlers and frameworks without React: `import { start, toast } from "cladux-html"`.
- [Installation](/docs/installation#the-cn-helper) explains the `cn()` helper.

- The plain HTML stylesheet mirrors too.

### New components

- [Number Ticker](/docs/components/number-ticker): a number that counts up to its value, or rolls its digits like an odometer, when it comes into view and whenever it changes.
- [Image Compare](/docs/components/image-compare): a before and after slider. Drag anywhere on it or use the arrow keys, side by side or top and bottom.
- [Date Range Picker](/docs/components/date-range-picker): a calendar for picking a range of days, with presets like "Last 7 days" and your own.
- [Dock](/docs/components/dock): a macOS-style bar of icons that grow as the pointer passes over them, and a toolbar you can use from the keyboard.
- [Signature Pad](/docs/components/signature-pad): draw a signature with a mouse, a finger or a pen, and export it as a PNG or an SVG, or send it with a form.
- [Animated Text](/docs/components/animated-text): four more effects. `flip` and `bounce` bring text in, `wave` lifts each letter in turn, and `glitch` slices it into colored copies.
- [Contribution Graph](/docs/components/contribution-graph): a year of activity as a grid of days, like GitHub's, in your theme's colors. Hover or use the arrow keys to read each day, and make days clickable.
- [Image Cropper](/docs/components/image-cropper): move and zoom an image under a frame, with any aspect ratio or a circle for avatars. Drag, scroll, pinch or use the keyboard, then export the crop at full quality as a PNG, JPEG or WebP.
- [Mention Input](/docs/components/mention-input): a textarea that suggests people when you type @, from a list or your own search. Mentions are highlighted and stay plain text.
- [QR Code](/docs/components/qr-code): a QR code drawn as an SVG in your theme's colors, in classic, rounded or dot styles, with an optional logo in the middle.
- [Masonry](/docs/components/masonry): items of different heights packed into even columns, in reading order, laid out by CSS before JavaScript loads.

### CLI 0.4: themes and AI

- **Theme codes.** Every theme on [Themes](/themes) has a short code, such as `zinc-violet` or `stone-rose-lg`, and the page keeps it in its URL so you can share a theme.
- **Apply one.** `cladux apply zinc-violet` rewrites your theme variables in your project's style, and `cladux init --theme zinc-violet` starts with one. See [apply](/docs/cli#apply).
- **In the library too.** [`cladux-registry`](/docs/registry#theme-codes) reads theme codes and turns them into CSS, in Node and in the browser.
- **An MCP server.** `cladux mcp` lets AI assistants in Claude Code, Cursor and VS Code search components, read their docs, add them to your project and apply themes. See [MCP server](/docs/mcp).

### CLI 0.3: your own registries

- **Build a registry.** List your components in `cl-registry.json` and run `cladux build`. It finds the dependencies from your imports and writes both styles, so projects without Tailwind can install your components too. See [build](/docs/cli#build).
- **Install from other registries.** Name them in `cl.json` and run `cladux add @acme/fancy-card`, with headers for private ones. See [Other registries](/docs/cli#other-registries).
- **Check a registry.** `cladux registry validate` finds missing files, unknown dependencies and imports `add` wouldn't install.
- **JSON schemas.** `cl.json`, registry items and `cl-registry.json` autocomplete in your editor, and every command checks `cl.json` before it starts.
- **A library.** The registry code is on npm as [`cladux-registry`](/docs/registry), for tools of your own.

### Docs for AI assistants

- [`/llms.txt`](/llms.txt) lists every docs page for AI assistants, and [`/llms-full.txt`](/llms-full.txt) has them all in one file.

### CLI 0.2

The CLI is on npm as [`cladux-ui`](https://www.npmjs.com/package/cladux-ui). Version 0.2 adds:

- **Find things.** `list` and `search` show components and blocks, with the installed ones and the new ones marked. `view` prints an item's files without installing it, and `docs` prints its docs page.
- **Check before you add.** `add --dry-run` lists what would be written, `--view` prints the files, and `--diff` shows what would change in files you have. `--path` puts a component in another folder.
- **Stay up to date.** `diff` shows how your components differ from the registry. `update` brings them up to date and keeps the files you changed.
- **The rest.** `info` shows your setup, `--silent` runs without output, and `-v` prints the version.

See the [CLI docs](/docs/cli) for every option.
