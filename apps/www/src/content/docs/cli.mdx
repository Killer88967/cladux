Run it with your package manager's runner. The command is the same in every project:

<CliCommand args="<command> [options]" />

## init

Sets up your project: `cl.json`, the theme, the `cn()` helper and one line in your stylesheet. See [Installation](/docs/installation) for what it writes.

<CliCommand args="init" />

| Option            | What it does                            |
| ----------------- | --------------------------------------- |
| `--style <style>` | `tailwind` or `css` (default: detected) |
| `-f, --force`     | Overwrite an existing `cl.json`         |

## add

Adds components or blocks, everything they depend on, and their npm packages. With no names, it shows a list to pick from.

<CliCommand args="add button card dialog" />

| Option             | What it does                                                   |
| ------------------ | -------------------------------------------------------------- |
| `-a, --all`        | Add every component                                            |
| `-o, --overwrite`  | Replace files you already have (only what you named)           |
| `--dry-run`        | Show which files would be written and which packages installed |
| `--view`           | Like `--dry-run`, and print the new files                      |
| `--diff`           | Like `--dry-run`, and show changes to files you already have   |
| `-p, --path <dir>` | Put what you named in this folder instead                      |

Components added with `--path` live outside your components folder, so `list`, `info`, `diff` and `update` don't see them.

## Other registries

Install from other registries that use the Cladux format by naming them in `cl.json`, then putting the name in front of the item:

```json
{
  "registries": {
    "@acme": "https://acme.dev/r",
    "@internal": {
      "url": "https://registry.example.com/r",
      "headers": { "Authorization": "Bearer ${INTERNAL_TOKEN}" }
    }
  }
}
```

<CliCommand args="add @acme/fancy-card" />

- **Dependencies follow the item.** A plain name in its `registryDependencies` comes from the same registry; `@cladux/button` comes from Cladux, whatever registry the item is in.
- **Secrets stay out of the file.** `${INTERNAL_TOKEN}` is read from the environment, and the CLI stops with a clear message when it isn't set.
- **`view`, `docs`, `diff` and `update` take the same names**, as in `cladux diff @acme/fancy-card`.

`@cladux` always means Cladux's own registry, so other registries can build on its components.

## list and search

`list` shows every component and block. `search` shows the ones whose name or description matches. In a project, installed items get a green dot, and new components are marked **new**.

<CliCommand args="search date" />

## view

Prints an item's files and what it needs, without installing anything. In a project, the imports use your aliases.

<CliCommand args="view button" />

| Option            | What it does                                                   |
| ----------------- | -------------------------------------------------------------- |
| `--style <style>` | `tailwind` or `css` (default: from `cl.json`, else `tailwind`) |

## docs

Prints a component's docs page in the terminal, with the examples importing from your components folder, and a link to the page with live previews.

<CliCommand args="docs countdown" />

## info

Shows the CLI version, your framework, package manager and versions, your `cl.json` settings and aliases, and which components and blocks are installed.

<CliCommand args="info" />

## diff

With no names, lists the installed components that differ from the registry. With names, prints the changes: red lines are yours, green lines are the registry's.

<CliCommand args="diff button" />

## update

Brings installed components up to date. Files you haven't changed are replaced. Files you edited are kept and listed, so you can look at them with `diff` and merge by hand.

<CliCommand args="update" />

| Option        | What it does                          |
| ------------- | ------------------------------------- |
| `-f, --force` | Also replace the files you changed    |
| `--dry-run`   | Show what would change, write nothing |

To tell your edits apart, the CLI saves a fingerprint of every file it writes in `cl-lock.json`. Commit it with your project. Components added before version 0.2 have no fingerprints yet, so `update` keeps them if they differ. `update <name> --force` replaces them and starts tracking them.

## registry validate

Checks a registry folder or URL before you publish it. Without one, it checks the registry in your `cl.json`.

<CliCommand args="registry validate ./public/r" />

It checks `index.json` and every item file against the [schemas](/schema/registry.json), and for what a schema can't see:

- **Errors**: a missing file, a dependency that isn't in the registry, a circular dependency, two items writing the same file.
- **Warnings**: a file that imports a package or an item it doesn't list, so `add` wouldn't install it, and relative imports, which break once the files are installed.

It exits with code 1 when there are errors, so you can run it in CI.

## Options for every command

| Option             | What it does                                           |
| ------------------ | ------------------------------------------------------ |
| `-c, --cwd <dir>`  | Project folder (default: current folder)               |
| `-y, --yes`        | Use the defaults, no questions                         |
| `-s, --silent`     | No output, and no questions. Errors still go to stderr |
| `--registry <url>` | Use another registry URL or folder                     |
| `--skip-install`   | Don't install npm packages                             |
| `-h, --help`       | Show the help                                          |
| `-v, --version`    | Show the CLI version                                   |
